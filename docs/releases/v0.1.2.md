# TwinCAT Knowledge MCP 0.1.2

This software release adds five read-only documentation tools to the existing
four-tool stdio server. It is available as versioned GitHub Release assets, not
as a claimed PyPI publication. Documentation corpora, operator profiles,
credentials and databases are not included.

## Changes and compatibility

- `tc_find_symbols` and `tc_get_symbol` retrieve explicitly documented symbol
  declarations with source citations, exact normalized code and unknown fields.
- `tc_find_libraries` and `tc_get_library` retrieve documented library records.
  Documented versions never establish installed versions.
- `tc_lookup_error` preserves original error-code spelling and separates domains.
  Ambiguous candidates remain separate; there is no numeric-equivalence fallback.
- Typed extraction runs lazily over existing validated topic packages. Existing
  package formats, snapshot selection and the original four tools need no
  migration. Unsupported source formats produce honest missing coverage.

The typed implementation and schemas are retained from the reviewed development
candidate. The package, CLI and server now report ordinary version `0.1.2`.
`provenance.py` retains committed LF bytes with SHA-256
`741a3aabe3f6e2832508ea769d5bb6c0a2fac8a9aad6ae56d9d6f0b8cf5dde52`.
The wheel metadata path is `twincat_knowledge-0.1.2.dist-info/RECORD`.

## Assets and verification

Tag `v0.1.2` provides the wheel, source archive, `uv.lock`, hash-pinned build and
runtime requirements, nine-tool schema catalog, release receipt and
`SHA256SUMS.txt`. The receipt binds the actual source commit/tree and canonical
Git input bytes to artifact hashes and schemas loaded from the built wheel.

Verify downloads against the recorded SHA-256 values before use. Retrieval is
bound to versioned tag/asset URLs and exact hashes. Repository-level GitHub
release immutability is not asserted; a changed asset fails the pinned hash.
The receipt is an integrity record, not a signed vendor attestation.

With Python 3.12 or newer and uv, install into a separate environment using the
downloaded asset directory:

```sh
uv venv --python 3.12.10 ./knowledge-env
uv pip install --python ./knowledge-env/Scripts/python.exe --require-hashes \
  --find-links ./release-assets -r ./release-assets/requirements-candidate.txt
```

On POSIX, use `./knowledge-env/bin/python` instead. The requirements pin both
the wheel and its runtime dependencies; no development-machine wheel URI is
embedded. Download dependencies separately if an offline installation is needed.
Keep the previous environment and unchanged operator configuration for rollback.
Stop the client-owned MCP process before switching environments, then restart it.

## Validation and limitations

Windows/Linux CI covers Python 3.12.10 and 3.13.12, lint, formatting, types,
dependencies, unit/stdio/installed-artifact tests, and software builds. Independent
reviews cover the typed implementation and canonical packaging/receipt delta.
Synthetic tests establish behavior for the documented extraction grammar; they
do not establish coverage or performance on a real InfoSys corpus.

Real-document extraction acceptance remains open. It requires an explicitly
approved source sample, fixed source hashes, manually reviewed expected facts
and negative cases, provenance/code checks, coverage and resource measurements,
and documented acceptance. Unlabeled or title-mismatched declarations, arbitrary
prose, unknown metadata formats and unsupported error syntax are not extracted.
The full 15-tool catalog remains incomplete. This server cannot establish live
editor, compiled PLC or installed-library state and provides no PLC access,
engineering writes, runtime control or HTTP serving.
